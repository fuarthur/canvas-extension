# UI library research for Canvas Planning Calendar

Reviewed: 2026-10-12. Scope: simplify the existing vanilla JavaScript, Shadow DOM extension without changing its planning data model. Findings use upstream documentation/source; recommendations below are project-specific judgments rather than claims made by the libraries.

## Recommendation

Use Telegram UI's grouped settings and compact cell hierarchy as the visual reference; Radix's spacing/type system and interaction contracts as the consistency reference; and shadcn/ui's semantic tokens and locally owned components as the maintenance reference. Implement the small set of needed patterns in the existing DOM renderer. Adding React, Tailwind, or a broad component runtime is not necessary to achieve this redesign.

Local evidence: `package.json` has no production dependencies and builds with esbuild; `src/styles.js` owns the extension's CSS and already uses semantic `--cp-*` theme tokens. A dependency migration would therefore be additional work with little direct benefit for the requested reduction in UI complexity.

## Five patterns to apply

1. **Grouped settings with useful closed summaries.** Telegram's [`Section`](https://raw.githubusercontent.com/telegram-mini-apps-dev/TelegramUI/main/src/components/Blocks/Section/Section.tsx) separates related rows; its [`Cell`](https://raw.githubusercontent.com/telegram-mini-apps-dev/TelegramUI/main/src/components/Blocks/Cell/Cell.tsx) distinguishes title, hint, subtitle, and trailing content. Use a section label plus a short current-value summary, such as “Reminders · Off” or “Courses · 5 selected.” Keep frequent controls visible. Expand advanced estimation rules, semester configuration, and custom colors on demand. Do not wrap every single field in its own card.

2. **Progressive disclosure with visible consequences.** Move explanations, examples, chart methodology, and uncommon filters into named disclosures. Keep selected filter counts and active configuration summaries visible while closed. Preserve open state during ordinary rerenders so changing a field does not close its group. Use native `details`/`summary` where suitable; custom disclosures should follow [WAI-ARIA's disclosure contract](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) with Enter/Space activation and correct expanded state. Unsaved work, data-fetch failure, capacity conflicts, and validation errors remain visible without opening help.

3. **A stable navigation row and a separate action hierarchy.** Give the main screens short, stable text labels. Keep one clear primary action for the current screen; place secondary actions such as import/export/reset in a compact disclosure. An action list does not need `role="menu"` unless its menu keyboard behavior is actually implemented. For true tabs, follow [Radix's documented tab behavior](https://www.radix-ui.com/primitives/docs/components/tabs): active tab in the Tab sequence, arrow-key movement, Home/End, and an associated panel. Retain readable labels for unfamiliar icons.

4. **One quiet spacing/type system.** Adopt a small subset of [Radix's spacing scale](https://www.radix-ui.com/themes/docs/theme/spacing)—4, 8, 12, 16, 24, 32 px—and [paired font-size/line-height values](https://www.radix-ui.com/themes/docs/theme/typography). A practical starting point is 14/20 body text, 12/16 supporting text, and 20/28 page titles with system fonts. Use the existing theme tokens for surface, border, text, accent, and status colors; shadcn's [semantic token approach](https://ui.shadcn.com/docs/theming) supports consistent light/dark/custom themes. Reserve filled accent buttons for the primary action and use thin separators for ordinary rows.

5. **Concise feedback that stays accessible.** Replace permanent instructional paragraphs with short contextual help, but show errors in text near the action or field that needs attention. Auto-open a collapsed group containing an invalid field and keep the invalid value editable. [WCAG error guidance](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) requires detected input errors to identify what is wrong in text; color alone is insufficient. Detail/dialog overlays need clear names, visible close controls, managed focus, Escape handling, and focus restoration per the [WAI-ARIA dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

## Review targets

The redesign should make the next action apparent in Calendar, Tasks, and Plan; reduce repeated explanatory text; retain all existing settings; reveal active filters and unsaved changes; and preserve keyboard, dark/custom-theme, and narrow-screen behavior. Verify representative populated, empty, loading, error, and draft states visually. A shorter page that hides necessary recovery information is not a successful simplification.
