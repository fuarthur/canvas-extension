# Canvas 规划月视图扩展：设计稿

## 后续改进（已确认）

本节更新下文首版设计中的日历选择和完成规则：

- 增加独立 Settings 标签，按账号保存日历选择；未选择的上下文在发起活动和作业请求前排除。未保存配置时读取原生日历当前勾选项，原生 DOM 不作修改。
- 保留前后各六个月的范围，避免遗漏跨月规划；按账号在当前页面缓存目录和无权限结果五分钟，最多六个请求并发。“Retry calendar access”主动清除该缓存。
- 完成外观取当前用户 Canvas 完成状态或本地手动标记。Canvas 完成状态只读，详情明确显示来源；其余项目仍可手动标记和取消。刷新重新读取 Canvas 状态，不向 Canvas 写入。
- 全部所选日历被拒绝时，提供 Settings 入口供用户恢复；主动不选任何日历则正常显示空视图。

## 目标与范围

为 `https://canvas.illinois.edu/calendar` 提供可即时打开和关闭的独立规划月视图。用户能看见日历活动的完整起止区间，也能为作业安排从开始日到截止日的区间，并在扩展中手动标记完成。关闭视图后，Canvas 原生页面立即按原样显示。首版是供已登录 Illinois Canvas 的单个用户使用的 Chrome Manifest V3 扩展；无需服务器或 Canvas API 令牌。

## 用户体验

- 在 Canvas 日历页点击扩展工具栏图标，打开覆盖页面主体的规划月视图；再次点击、点关闭按钮或按 Escape 即关闭。扩展只挂载自己的 Shadow DOM 容器，不改写 Canvas 的日历节点、数据或样式。
- 初次打开时从 Canvas 日历 URL 的 `view_start` 读取月份；没有该参数时显示当月。视图提供上月、下月、今天和刷新按钮。关闭和重开时可保留上次浏览的月份。
- 月格中用横向色条表示从开始日到结束日的区间；跨周时在各周续接。区间在可见月份边界裁切。单日项目仍显示在当日。色条显示标题、所属日历和完成状态；过密日期可展开余下项目。
- 点击项目打开详情，展示原始 Canvas 链接、开始和结束时间。作业详情提供计划开始日选择器；所有项目都可勾选或取消“完成”。完成的项目继续可见，但外观明显区分。
- 日期优先按 Canvas 用户资料中的时区、未提供时按浏览器本地时区展示；悬停或详情中保留 Canvas 返回的精确时间。截止时刻不因按日绘制而改变。

## 日期与完成规则

- 普通日历活动使用 Canvas 的 `start_at` 和 `end_at`。若仅有其中一个有效时间，则按单日项目处理。
- 作业截止日使用 Canvas 对当前用户生效的 `due_at`。计划开始日默认使用该用户生效的 `unlock_at`。用户可以在扩展中调整计划开始日；显式设置的本地日期优先于 `unlock_at`。若无开放日期且尚未设置计划开始日，作业先作为截止日单日项目显示，并提示设置开始日。
- 计划开始日不能晚于截止日；无截止日的项目不进入月格，首版不提供无日期清单。
- “完成”是扩展独立的手动状态，可反复切换。它不代表已在 Canvas 提交，也不调用 Canvas Planner 的写入接口。

## 架构与数据流

1. Manifest V3 的内容脚本只运行于 Illinois Canvas 日历页。扩展工具栏按钮向该页发送切换消息；内容脚本创建或移除独立的规划视图。通过 Shadow DOM 隔离样式，避免影响原页面。
2. 使用当前已登录的 Canvas 会话，对同源 Canvas API 发起只读请求。读取当前用户 ID、活跃课程、所属小组和可见账号日历，再组合个人、课程、小组、账号日历上下文。日历接口每次最多接受 10 个上下文，因此分批请求并跟随分页，分别获取活动和作业。请求范围是浏览月份首日向前六个日历月的首日，至浏览月份末日向后六个日历月的末日；切换到已缓存范围外时重新获取。
3. 对作业优先读取日历响应所附的完整作业对象以取得生效的 `unlock_at` 和 `due_at`；缺少时按课程和作业 ID 查询作业详情。仅渲染当前用户可见的数据。不同批次与分页结果按“类型 + ID”去重，保留项目所属的全部上下文。
4. 将 Canvas 数据转换成统一项目 `{key, type, title, context, start, end, url}`，再合并本地计划开始日和完成状态。日期转换、跨周切分与界面渲染分开实现，方便验证。
5. `chrome.storage.local` 以独立键保存本地开始日和完成状态。键名包含 Canvas 域名与当前用户 ID；每个项目使用稳定的类型和 ID，避免共享浏览器里不同账号互相覆盖，也避免并发修改互相覆盖。浏览月份保留在当前页面的规划视图中；页面刷新后仍以 Canvas URL 的月份为准。扩展不向第三方服务传输日历内容。

## 异常与边界

- 未登录、接口拒绝访问或请求失败时，规划视图显示明确错误与重试按钮；关闭视图仍能直接使用 Canvas 原日历。
- 对 API 分页、10 个上下文限制、重复日历项、跨月与跨年区间、夏令时切换分别处理。异常日期不绘制为错误跨度，而显示可诊断的提示。
- 扩展只读取 Canvas 数据。Canvas 页面升级导致 URL 结构改变时，初始月份退回当月；视图本身不依赖 Canvas 日历的内部 DOM。
- 首版只针对 `canvas.illinois.edu`，不覆盖其他 Canvas 实例。无日期项目、Canvas 状态同步、跨设备同步和编辑 Canvas 原始活动均不在首版范围内。

## 验收与验证

- 打开/关闭扩展后，原生 Canvas 日历的内容、交互和刷新行为保持正常。
- 跨周活动在完整日期区间上连续显示；有开放日期的作业默认从开放日延续至截止日；没有开放日期的作业设置本地开始日后形成区间。
- 重新载入页面后，本地开始日和完成标记仍在；切换 Canvas 账号不会看到另一账号的本地状态。
- 作业详情始终链接到原始 Canvas 项目；完成标记不会改变 Canvas 中的提交或 Planner 状态。
- 用日期边界和 API 数据样例验证转换逻辑，再在 Chrome 中加载未打包扩展，检查切换、分页、错误提示和本地保存。Illinois 实际登录态下的页面表现需在可访问该账号的浏览器中最后核实。

## 依据

- [Canvas Calendar Events API](https://developerdocs.instructure.com/services/canvas/resources/calendar_events)：活动有起止时间，作业日历项的起止时间均为截止时间；接口分页，上下文每次最多 10 个。
- [Canvas Assignments API](https://developerdocs.instructure.com/services/canvas/resources/assignments)：作业提供对请求用户生效的 `due_at` 与 `unlock_at`。
- [Chrome 内容脚本](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts)及[扩展存储](https://developer.chrome.com/docs/extensions/reference/api/storage)：内容脚本独立运行，扩展状态可保存在 `chrome.storage.local`。
