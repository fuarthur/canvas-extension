# Canvas 作业截止提醒设计

日期：2026-10-04。状态：用户已确认访谈中的推荐行为和完整聊天设计；本文件等待审阅。产品代码尚未修改，实现计划尚未编写。

## 目标与范围

在现有 Settings 中增加可关闭、可配置的作业截止提醒，帮助用户在 DDL 前处理尚未完成的作业。默认关闭；开启后的初始配置为一轮、提前两小时。Canvas 页面关闭后，只要浏览器仍在运行，后台仍可同步数据并触发桌面通知。

首版覆盖当前已验证账号、已选日历中的 Canvas 作业，只使用真实 `dueAt`。已有 Canvas 提交状态或扩展本地完成标记均视为完成。无有效 DDL、已过期、已完成的作业不提醒。个人计划完成时间、日历活动和计划工作时段不参与；当前仓库没有独立的手动任务创建功能，本次不新增该功能。

用户确认的行为包括系统桌面通知、每轮独立配置提前时间、当前账号和日历范围、恢复运行时只补最近一轮，以及断网、DDL 变化、修改配置后的处理规则。成功标准是默认值正确、配置可保存、正常运行时按指定时间发出通知、已发送轮次不重复、账号切换后不继续发送旧账号提醒。

## Settings 交互

在规划设置中新增独立的「DDL 提醒 / Deadline reminders」区域，沿用现有设置的编辑和保存流程。修改草稿不直接启用提醒；保存成功后生效。保存失败保留草稿并提供错误反馈。

| 控件 | 行为 |
| --- | --- |
| 开启提醒 | 默认关闭；关闭后停止自动提醒并保留已保存配置和发送记录 |
| 提醒轮数 | 1–5 轮；轮数由保存后的独立提前时间数量决定 |
| 每轮提前时间 | 1 分钟至 30 天，输入数值并选择分钟、小时或天 |
| 通知状态 | 显示关闭、等待首次同步、正常运行、离线使用最近数据、数据过期暂停、需要登录或通知不可用 |
| 最近同步时间 | 使用最近成功获取提醒数据的时间，不用失败请求时间代替 |
| 发送测试提醒 | 用户点击后发送不含真实作业信息的测试通知，不修改作业发送记录；功能关闭时也可测试 |

存储统一使用整数分钟，范围为 1–43200。允许能精确换算为整数分钟的输入，例如 0.5 小时；不接受零、负数、非有限数或小于一分钟的结果。保存时从最早提醒到最晚提醒排序，即提前分钟数从大到小排序，并合并重复时间。合并后同步显示实际轮数。

增加轮数时保留已编辑的时间，并从 2 小时、6 小时、1 天、2 天、3 天的预设中补入尚未使用的值；用户可逐轮修改。减少轮数时保留距离 DDL 最近的所选数量，并在当前草稿中展示结果。初始值始终只有提前 120 分钟的一轮。

提醒轮次控件在开关关闭时禁用，但保留其值。状态和测试按钮保持可用。所有标签、通知、状态和错误均支持英文、简体中文；通知使用对应账号保存的语言和 Canvas 时区。窄屏逐行排列，保留输入标签、键盘操作和可访问的状态反馈。

## 提醒时间与去重

每轮触发时刻为 `dueAt - leadMinutes × 60000`，使用绝对时间计算；展示时按账号时区格式化，跨时区及夏令时不改变同一个真实 DDL。

正常运行时，每个作业的每轮提醒各发送一次。发送记录的身份由站点、账号、作业 key、DDL 的规范化时间和提前分钟数组成，不依赖界面上的轮次序号，因此排序、重复时间合并和账号切换不会误触发重复提醒。

恢复运行、首次开启或新增轮次时，若已有轮次到点且 `now < dueAt`，只考虑当前配置中已经到点的最晚一轮。该轮未发送才补发；若已经发送，不再追溯更早轮次。更早的已错过轮次记录为跳过，未来轮次正常安排。`now >= dueAt` 时不发截止提醒。

DDL 改变后取消原时间的后续提醒，按新 DDL 重新计算，并使用新的 DDL 身份记录轮次。若 DDL 改回曾出现的时间，该时间下已有的发送记录仍有效。作业完成后取消未来提醒；撤销本地完成后恢复未来轮次，并按上述补发规则处理当前最近一轮，已发记录保留。Canvas 完成语义继续复用现有模型。

保存配置、切换日历、关闭再开启时重新计算安排，保留同一身份的发送记录。关闭功能不清空配置或历史；从范围中移除、删除或失去访问权限的作业不继续发送旧安排。

## 后台运行与数据更新

采用「每 15 分钟更新数据 + 按具体提醒时间设置下一次触发」的本地方案。只做定期检查会使通知偏晚；只建立定时任务无法及时发现 DDL 或提交状态变化；两者结合满足此次功能。无需外部服务。

后台使用一个更新用的周期 alarm 和一个最近触发时间用的 alarm，而不是为每个作业、每个轮次建立独立 alarm。最近触发到点后重新读取持久状态、检查资格并处理该时刻已到点的作业，再安排下一次。

启用后立即核验登录身份并首次同步。每 15 分钟同步一次；提醒触发前再尝试刷新，优先使用新的 DDL 和提交状态。背景读取使用现有 Illinois Canvas 主机权限和登录 Cookie，只执行读取请求。复用现有账号核验、分页、日历选择和模型规范化能力，加载以当前时间为基准的提醒范围，而不是沿用界面正在查看的历史月份。查询范围覆盖今天至最长提前时间之后，并为账号时区的日期边界留一天余量；最终按绝对 DDL 筛选。

提醒数据使用独立持久快照，保存作业 key、标题、课程名称及 context codes、DDL、作业链接、Canvas 完成状态、账号时区和成功同步时间。已有日历缓存可继续供界面使用，但其淘汰、体积限制或浏览月份不会使后台提醒丢失。

短暂断网或服务暂时失败时，最近一次成功同步的数据在 24 小时内仍可用于提醒，发送前始终叠加最新本地完成标记和当前已选日历。达到 24 小时后暂停发送；定期同步继续尝试，恢复成功后重新安排并应用补发规则。失败请求不刷新快照的新鲜度。

检测到身份验证失效时立即暂停发送并使旧提醒快照失效。后续周期只尝试核验登录，核验成功后读取该账号设置，再同步提醒数据；页面验证登录也可触发恢复。明确无访问权限的日历从可发送范围排除；部分成功的同步不把无法访问的数据当成完整有效数据。

浏览器完全退出时无法准时运行本地扩展；电脑休眠时 alarm 不会唤醒设备，恢复后可能触发错过的 alarm。Chrome 也可能延迟 alarm，因此准时是正常运行下的目标，不是硬实时保证。每次后台启动、浏览器启动、扩展安装或更新后，依据持久状态检查并恢复所需 alarm，不依赖内存计时器或高版本专有的 alarm 持久化选项。[Chrome alarms 说明](https://developer.chrome.com/docs/extensions/reference/api/alarms)

## 账号与持久状态

新增设置字段 `reminders: { enabled: false, leadMinutes: [120] }`，保存在现有账号级 `settings:v1` 中。旧设置缺少该字段时补默认值，不使整份旧设置失效，也不自动启用功能。非法提醒字段只使提醒功能回退为关闭及默认时间，并产生可见警告；其余合法设置和原始存储记录保留。保存新的草稿时严格校验提醒字段。

按现有 `canvas-planner:<hostname>:<userId>:` 前缀保存提醒快照、发送记录、运行状态和通知点击映射。站点级另存「最近验证账号」指针；外观模块的账号提示不作为提醒身份依据。指针只用于恢复最后验证账号的本地运行状态，不能证明一次新请求的当前登录身份。

前台在取得已验证 profile 后通知后台核对账号；后台独立核验身份后更新活动账号。每次背景同步也先核验身份，再读取该账号的设置和作业。发现账号切换时立即停止旧账号安排，读取新账号自己的开关和配置：若未开启则保持关闭。已登录账号身份变化、选择变化或配置变化期间，迟到的旧请求不得写入新状态或发送旧通知。

提醒状态的写入和投递由后台统一串行处理。异步操作使用运行版本检查，并在发送前重新确认活动账号、设置开关、日历选择、完成状态、快照新鲜度和 DDL。

投递先持久写入轮次占位，再调用通知 API；成功后记录已发送，明确失败可释放占位并显示错误。若后台在通知调用期间被中断，无法确定已展示与否的轮次不自动重复投递，以优先满足去重；运行状态记录该异常。Chrome 存储失败时不在缺少去重记录的情况下发送。旧记录只在相关 DDL 已过期且通知点击映射不再需要时清理，未过期轮次不能因整理记录而重复发送。

## 通知与权限

新增 `alarms`、`notifications` 扩展权限，保持现有 Illinois Canvas 主机范围。兼容现有 Chrome 114 构建目标；通知 API 使用兼容回调的封装，不能因直接使用较高版本才支持的 Promise 接口提高最低要求。

采用 basic 桌面通知，每个作业独立发送。显示真实作业名称、课程、剩余时间和具体 DDL；临近截止的剩余时间至少显示一分钟，避免显示零分钟误导。使用扩展内静态图标，构建时一并复制。点击通知打开对应作业，不提供暂缓、完成或自定义声音等额外操作。

通知链接只允许现有 Canvas HTTPS 站点。无有效作业链接时打开 Canvas 日历；测试通知也打开日历。账号已经切换、退出或该作业已完成时，清除相关可见通知和旧点击映射，避免旧任务链接继续作为活动提醒。

Settings 显示浏览器报告的通知权限。权限被拒绝、API 失败或扩展上下文失效时显示对应错误；没有创建成功的通知不记录为成功发送。API 成功只能证明已请求系统通知，不能证明用户看到了横幅，勿扰模式等系统行为须通过真实通知验证。[Chrome notifications 说明](https://developer.chrome.com/docs/extensions/reference/api/notifications)

后台网络读取能力受现有主机权限约束，真实 Cookie 登录在后台的成功与否须实际验证，不能用模拟响应当作已验证。[Chrome 网络请求说明](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

| 模块或现有文件 | 职责 |
| --- | --- |
| 新提醒设置模块 | 默认值、输入换算、校验、归一化和旧设置兼容 |
| 新提醒规则模块 | 资格筛选、触发时间、最近一轮补发、轮次身份和去重决策；不依赖 Chrome |
| 新提醒服务模块 | 数据同步、账号切换、持久状态、串行投递、通知状态和下一次触发 |
| 新提醒客户端及 Chrome 适配 | 前台状态和测试消息、alarm 和通知 API 封装、固定 Canvas 链接处理 |
| `src/background.js` | 同步注册生命周期、alarm、通知点击、设置变化和提醒消息监听；继续保留原计划和排程服务 |
| `src/canvas-api.js`、`src/model.js` | 复用或小幅抽取登录核验与提醒读取入口，沿用真实 DDL 和完成语义 |
| `src/planning-settings.js`、`src/storage.js` | 兼容缺失提醒字段、账号级保存及变化通知 |
| `src/settings-view.js`、`src/content.js`、`src/view.js` | Settings 编辑、保存和状态显示，已验证账号及日历范围与后台衔接 |
| `src/i18n.js`、`src/styles.js` | 中英文文案和窄屏设置布局 |
| `manifest.json`、`scripts/build.mjs`、图标资源 | 定时及通知权限、打包静态通知图标 |
| 现有及新增测试 | 规则、服务、设置、权限契约、构建和回归验证 |

提醒消息必须验证发送页面属于已授权 Canvas 顶层页面，并结合已核验账号校对请求；不接受任意站点、任意账号或任意请求 URL。只读数据保存在本机扩展存储，不引入第三方服务、遥测、额外依赖或 Canvas 写入。现有用户设置、完成记录、计划和安装身份保留。

## 验收与交付

规则测试使用固定时钟和作业样本，覆盖默认关闭与提前两小时、1–5 轮、单位换算与边界、重复合并、正常触发、临界 DDL、无截止时间、完成和撤销完成、跨时区及夏令时、错过多轮只补一轮、已经发送最近一轮时不追溯旧轮次、修改配置、DDL 改动与恢复旧 DDL。

服务测试使用可控存储、Canvas 响应及 Chrome 适配，覆盖页面关闭后的运行、持久恢复、丢失 alarm 重建、多个同刻作业、重复事件与并发请求、发送失败、占位期间中断、存储失败、过期快照、身份失效、账号切换、日历范围和部分无权限、迟到响应、关闭立即停止及通知点击目标校验。模拟请求不使用真实用户数据。

设置测试覆盖旧记录迁移、非法提醒字段不破坏其他设置、编辑草稿与保存生效、保存失败保留输入、重复时间反馈、关闭保留配置、通知状态和测试反馈。浏览器检查覆盖英文、中文、浅色、深色和桌面及约 390px 窄屏，确认输入、焦点和状态可读。

运行完整 `npm test`、`npm run build` 和 `git diff --check`，核对打包权限、后台监听、图标资源和原有功能回归。真实验证单独检查后台 Cookie 登录、Canvas 页面关闭后的同步和桌面通知、点击作业链接、浏览器重启后的恢复；真实验证无法执行的部分明确列为未验证，不以自动化模拟代替。

本次交付为本地功能实现、构建和验证记录。GitHub 发布、版本发布和 Canvas 作业提交不属于本次范围。规格审阅后编写实现计划，再选择当前会话执行方式。
