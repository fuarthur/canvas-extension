# Canvas 工作量与多计划排程：设计稿

## 1. 目标和已确认方向

在现有 Illinois Canvas 扩展中完成一套工作量规划流程：看清截止压力，填写或自动推导估时，把未完成任务安排到工作日，生成尽量均衡的计划，并保存、调整和比较多个方案。

用户已确认采用 Calendar、Workload、Planner、Settings 四个标签。入口继续位于 Canvas 的 Week / Month / Agenda 后；新增功能均在扩展容器内，不修改原生日历内容，不向 Canvas 写入。Canvas 当前用户完成状态和本地完成标记沿用现有逻辑；所有新数据按域名和用户账号保存在 Chrome 本地存储。

任务拆分采用推荐默认：作业允许跨天安排，每项可设置“必须一次完成”。普通日历活动默认是固定时间项目，不由生成器改动日期。用户提供的两张参考图分别用于日期折线和按 Today、Tomorrow、具体日期组织计划的交互方向，界面沿用本扩展现有风格。

成功标准：用户能区分截止日工作量与计划工作量；估时规则可解释；手动和自动安排都能检查截止冲突；多个计划相互独立且可比较；加载、账号隔离、日历筛选和原生页面切换不退化。

## 2. 界面结构与统计口径

### Calendar：日期压力标记

- 在规划月历每个日期数字旁增加未完成项目数量徽标。作业按生效截止日计一次；固定活动按开始日计一次。跨日开放区间不重复计数。
- 默认 0–2 项为绿色、3–5 项为黄色、6 项及以上为红色。零项用低强调的绿色样式；Settings 可修改黄色、红色的起始数量，要求 `1 <= yellowFrom < redFrom`。
- 徽标同时展示数字、文字说明和可访问标签，颜色不是唯一信息。点击打开当日清单，展示项目、估时、课程及完成操作。
- 顶部 Today 旁展示今天剩余数量与独立的逾期数量。逾期依据当前时刻与原始截止时刻判断，不因浏览过去月份改变。
- 已完成项目仍按现有样式留在月历，但不进入剩余数量或时长。

### Workload：截止压力曲线

- 横轴是浏览月份日期，纵轴切换 Tasks 或 Estimated hours。月外日期不计入月总数。
- 数量是该日尚未完成的唯一项目数；作业时长是估时总和，固定活动时长也仅在开始日计一次。不是开放期间每天重复加同一项。
- 图旁显示月总数、总估时和峰值日，并说明“按截止日统计；活动按开始日统计”。逾期另列，不累计到今天导致混淆。
- 点击图中日期打开当日清单；提供等价的日期数据表，零值连续显示，空月份有正常空态。
- 使用本地 SVG 和原生交互绘制折线，不引入在线图表服务。数量轴为整数，时长轴显示小时，详情保留分钟。

### Planner：双栏工作台

- 左侧是加载范围内的未完成任务。支持标题关键词搜索（忽略大小写、去首尾空格）、课程/日历筛选、按课程分组，以及截止时间或估时的升降序。多日历归属项目只安排一次；分组时在主要课程组显示，并列出其他归属。
- 列表区分未安排、已安排和部分安排，可显示全部，避免安排后找不到任务。逾期项目单独突出展示。
- 右侧按日期分组：Today、Tomorrow、具体日期。组头展示任务数与预计总时长；较远日期可折叠，空工作日仍可作为放置目标。
- 支持拖动到日期、修改日期/时长、调整同日顺序、移除安排，以及等价的按钮和表单操作。拆分任务显示“本段分钟 / 任务总分钟”。
- 手动安排可指定起始时间；只选日期时，由当天可用窗口内的空闲时间建议具体位置，保存前展示建议。分段存储具体起止时刻，列表默认精简为日期和时长，冲突或展开详情时显示时间。
- 手动安排允许保存有冲突的草稿，但要明确标记未满足的时间、估时或截止约束，不能标记为有效计划。超出任务估时的分配需要先修改估时，避免重复计算。
- 计划曲线按工作发生日汇总，与 Workload 分开标注。默认显示尚未完成任务的计划时长；已完成项目留在计划中并划线，贡献为零。曲线也可切换当天唯一任务数。

### Settings

保留日历筛选；新增估时规则、压力阈值和新计划默认排程配置。配置保存后本地重算，无需为估时或颜色变化重新请求 Canvas。

## 3. 估时规则

- 每个 event/assignment 可手动填写预计分钟数，范围为 1–1440 的整数；可清除手动值恢复规则值。必须一次完成的开关与估时独立保存。
- 优先级固定为：有效的手动估时 → 第一条启用且匹配的规则 → 全局默认值。初始全局默认 60 分钟。
- 规则支持“标题包含关键词”和“属于某个课程/日历”。关键词匹配忽略大小写；课程用稳定 context code 匹配，不用课程显示名做身份。
- 每条规则有名称、匹配类型和值、估时分钟数、启用状态；支持新增、编辑、删除、上下移动。没有规则时使用全局默认。空关键词和非法分钟数不可保存。
- 多条命中时第一条生效。详情显示 Manual、Rule: 名称或 Default，设置页提供标题/课程预览，便于检查 HPDL 30 分钟和 EPSY 456 60 分钟等配置。
- 不执行用户输入的 JavaScript 或表达式；用上述规则编辑器实现自动默认值。
- 固定活动也能填写估时，但实际起止时刻仍取 Canvas。估时用于工作量统计，真实活动区间用于排程占用，二者分别标注，避免把估时误当活动实际长度。

## 4. 计划存档与比较

- 每个计划有稳定 ID、名称、创建/更新时间、范围、排程配置、参与任务清单、任务信息快照、工作分段、锁定状态和手动顺序。
- 支持新建空计划、新建自动计划、保存、更名、复制、删除。删除只影响扩展内该计划，需显示计划名确认；删除最后一份后回到新建空态。
- 使用显式 Save 保存草稿；未保存切换、关闭或删除当前计划时提供保存、放弃或返回。复制产生独立 ID，修改 A 不改变 B。
- 默认新计划从今天开始，覆盖 28 个日历日；范围可修改，最多 180 天。默认包含范围结束前到期、尚未完成且可见的作业及范围内固定活动；范围外任务可手动加入，并在界面标明未纳入的未来任务数。
- 选择 2–4 个计划对比，使用同一日期轴和纵轴，以不同颜色和图例展示每日曲线、总估时、峰值日、未安排分钟数和截止冲突数。图外提供表格；不同范围取日期并集，不同范围外的日期显示无数据，不伪装为休息日零值。
- 存档保留生成/保存时的估时和分段。新的默认值或规则不会静默改写已保存计划。当前任务数据变化时提示估时、截止或完成状态变化；用户可显式“更新任务数据”，再校验和重新安排。
- 校验截止和开放限制始终使用当前已加载的 Canvas 事实。存档截止时间与当前值不同时，生成前需要确认更新快照；旧存档可以查看，但不能靠旧截止时间获得成功状态。
- Canvas 和本地任务完成状态始终是实时共享事实：所有计划中同一任务均显示完成，剩余工作量归零。存档分段不被删除，比较可以切换“保存时安排”与“当前剩余”，两种模式标注明确。
- 日历取消选择或 API 暂不可用时，不删除旧计划引用；显示保存的标题和“当前未加载，无法核验”。含未知任务的计划不能宣称已完整通过截止检查。
- 本轮不新增执行计时器或分段实际完成记录。勾选完成表示整个任务完成；拆分段的锁定仅控制是否允许自动重新安排。

## 5. 排程约束和生成方式

### 可用时间

- 每周各日配置可用工作窗口与最多工作分钟，默认每天 09:00–21:00、最多 240 分钟，无自动指定休息日。
- 休息日容量为零，低负荷日设置更小的每日分钟上限。日期例外可覆盖某一天，支持临时放假或增加容量。
- 工作窗口、活动占用和分段必须按 Canvas 用户时区转换。当前日排除已经过去的时间。当天窗口与活动的重叠区间取并集，只扣一次。
- 固定活动保留真实起止时刻，扣除与可用窗口重叠的时间。未完成活动的估时计入该日压力；跨日固定活动按实际区间逐日占用，不重复计当天到期任务数。
- Planner 曲线中的跨日活动估时按各当地日期所占真实活动分钟的比例分摊，总量保持不变；零时长活动全部计入开始日。活动占用的是实际区间，不能因为估时较小而释放该区间。
- 默认选中的日历数据用于统计和排程；保持已有过滤和缓存机制。计划范围需要落在已完整加载的数据范围内，超出时先加载需要的范围；有未加载日历时明确提示计划只覆盖可见数据。

### 作业约束

- 最早可工作时刻是今天/计划开始日、Canvas 真实开放时刻以及用户设置的计划开始日三者中的最大值。手动开始日不能绕过真实开放限制。
- 没有 Canvas 开放日期的作业，生成器允许从计划开始日安排，不把现有月历“截止日单日显示”的回退日期当真实开放日期。用户设置的开始日仍作为约束。
- 所有分段结束不得晚于真实 `due_at`；截止日中午的作业不能被安排在当天下午。默认偏好至少提前一天完成，但这是软偏好，必要时可安排到截止时刻之前。
- 允许拆分的作业可以跨日；必须一次完成的项目要求一个连续空闲区间。不改变 Canvas 截止时间或提交状态。
- 锁定的有效分段和固定活动保留；无效锁定、重复时间、超出估时、过期分段或已有截止冲突先列出，用户处理后再生成。
- 已逾期且未完成的任务不能生成“按时”计划：单列为逾期，允许手动补做安排，仍保留逾期标记。计划范围之外的截止任务不被悄悄视为已覆盖。

### 生成和均衡

1. 用当前数据与计划快照构造任务、剩余估时和可用时间区间；验证锁定安排并扣除占用。
2. 先处理必须一次完成的任务，优先截止早、可行空闲区间少的项目；在满足限制的候选区间中优先低负荷日。采用确定性候选选择和有限回溯，避免无界搜索。
3. 对可拆分任务按时间推进，优先分配当前已开放且截止最早的任务；遇到开放、截止、固定占用和容量边界切分。内部分钟精度，不把原始截止时间四舍五入放宽。
4. 得到满足硬约束的初始分段后，将未锁定的分段移到合法且负荷更低的日期，降低每日估时峰值和负荷离散程度，同时优先减少临近截止的安排。容量较低日按相对可用容量比较，零容量日不参与均衡。
5. 合并同日相邻的同任务分段，校验完整结果：任务分钟数守恒、没有重复安排、没有时间重叠、符合容量/开放/截止约束。只有校验通过且所有参与的可按时任务已完整安排，才显示“已安排，截止检查通过”。
6. 展示预览，用户接受后写入当前草稿，再由 Save 持久保存；生成器不覆盖旧存档或锁定安排。支持取消。

这是可解释的本地约束排程与均衡算法，不承诺数学上的全局最优。必须一次完成的任务组合若有限搜索未找到方案，提示“未能安排，请调整或允许拆分”，不声称已证明无解。确定的缺口（总容量不足、任务开放晚于截止、找不到任何连续窗口等）给出对应原因与分钟数；存在未安排项时保留安全的部分预览，但不展示全覆盖成功。

计算放入扩展已有的 Manifest V3 后台 Service Worker，通过内部消息启动并分批让出执行，设置计算预算并可取消，避免阻塞 Canvas 页面。超过预算返回明确的未完成状态和当前候选结果，不无限等待。后台意外重启时显示可重试状态，草稿不受影响。结果中带任务/配置版本，计算期间数据发生变化时废弃旧结果或要求重新校验。

## 6. 紧急程度

- 默认当前时刻距真实截止不超过 24 小时为红色高优先级，24–72 小时为黄色；逾期为红色并标明 Overdue。
- 计划中的最后分段距截止不足 24 小时，额外显示 Tight deadline，不论当前距截止是否很远。结束晚于截止则是 Deadline conflict，不能混同普通紧急提醒。
- 排序和提醒使用原始时间戳；完成任务不显示待办紧急提醒。距离说明显示具体小时/天数，颜色之外有图标和文字。

## 7. 模块边界与数据

现有 `view.js` 集中处理整套页面，新增功能不继续堆入该文件。保留入口和整体状态协调，把新增功能按职责拆分。

- `model.js`：保留身份、去重、完成规则；补充原始 context codes、真实开放/截止、固定活动时间等，区分展示跨度与排程约束。
- `estimates.js`：纯函数验证规则并计算有效估时和来源，不访问 Canvas 或 DOM。
- `workload.js`：纯函数生成截止日数量/时长、逾期统计和压力等级。
- `plans.js`：计划快照、分段、草稿变更、统计、实时完成状态合并和冲突校验。
- `scheduler.js`：排程核心，不依赖 DOM 或 Canvas 请求；`scheduler-service.js` 在现有 `background.js` 的后台 Service Worker 中承接运行和取消，无需新增内容页 Worker 或权限。
- `chart-view.js`、`workload-view.js`、`planner-view.js`：SVG 图表与各标签界面；共用现有详情的估时/完成操作。
- `storage.js`：扩展版本化配置、每项估时/拆分选择和每份计划的独立键；读取时验证，不把非法记录当有效计划。
- `view.js`：协调加载、账号变化、四个标签和详情。设置、规则与计划本地编辑不触发 Canvas 重新加载；需要新范围或刷新完成事实才走现有加载器。

存储沿用 `canvas-planner:<hostname>:<userId>:` 前缀，新增 `settings:v1`、`estimate:<itemKey>`、`single-session:<itemKey>`、`plan:<planId>`。计划记录含 schemaVersion；每份单独保存，避免两个计划互相覆盖。旧开始日、完成状态和日历选择不迁移、不丢失；无新配置时使用上述默认值。

计划保存带修订号，监听同账号存储变化。计划保存/删除通过后台按账号和计划 ID 串行执行，并比较期望修订号，避免仅在页面读取后写入造成竞争。不同计划可独立编辑；同一计划在另一页面更新时标记冲突，不静默覆盖，提供重载或另存副本。配置和估时以最新保存为准，并提示当前草稿需要重新校验。

用户输入仅通过文本节点和受控字段渲染；原有 Canvas 链接同源检查继续生效。权限保持 storage 与 canvas.illinois.edu，不新增第三方网络请求。

## 8. 异常、性能与可访问性

- API 错误仍能进入 Settings；旧计划可以以快照方式查看，但无法核验当前任务时标注其限制。
- 存储失败保留草稿并显示重试，不展示已保存。非法配置字段回退到默认并提示；非法计划保留记录，不用损坏数据生成排程。
- 账号切换清空上一账号内存状态、草稿和 Worker 结果，重新按当前账号加载。
- Canvas 完成变化会在刷新后同步到全部视图；同页面本地完成操作即时更新数量和曲线。图表、规则与计划切换不重新请求数据。
- 图表和列表按当前范围计算，较长计划日期折叠；拖动之外提供键盘可用操作。图表附数据表和说明，焦点与当前选择在局部重绘后保持。
- 保留原生日历入口去重、工具栏重建恢复和关闭后原生视图操作。关闭有未保存草稿时先处理草稿；关闭或账号变化取消后台排程。

## 9. 验收与测试

1. 月历日期徽标、Today 和图表对完成/未完成、跨日、重复来源、跨月、逾期和用户时区的统计一致；完成后立即减少，原生日历内容不变。
2. 手动估时优先；清除后恢复规则；HPDL、课程规则、顺序、禁用、默认及错误输入均有可解释结果；账号隔离且重开保留。
3. Planner 搜索、课程分组、两种排序、手动日期/时间分配、拆分、移除和锁定工作正常；未保存草稿不会误称存档。
4. 保存/复制/更名/删除不影响其他计划；完成事实跨计划共享；估时或截止变化不会静默改写存档；多计划比较使用共同坐标和明确模式。
5. 排程覆盖开放日期为空、未来开放、午间截止、当前时间、固定活动重叠、每日容量、完全休息日、低负荷日、连续任务、锁定、已逾期、容量不足与有限搜索未找到方案。
6. 自动生成的成功结果必须逐项通过独立校验；用小规模穷举样例检查可拆分案例，防止仅测试实现本身。比较均衡前后的每日峰值与离散程度，均衡不得引入截止或容量冲突。
7. 日期/区间测试覆盖夏令时、不同用户时区、跨年和日期边界。Worker 测试覆盖取消、超时与数据变更后旧结果不应用。
8. 在 Chrome 中验证实际已登录 Canvas 的数据、原生入口、四个标签、设置重开、规则预览、计划保存/对比和活动占用；保留完整自动化测试与构建检查。

## 10. 实施顺序

先完成数据与存储、估时规则和压力统计；再加入 Calendar 徽标与 Workload；然后实现多计划的手动双栏工作台与比较；最后接入约束校验、Worker 自动均衡排程，并完成实际 Chrome 验证。这些是同一功能的交付顺序，最终范围包含本稿所有功能，不将自动排程或多计划留为未实现建议。
